GitHub Copilot CLIを使って、Tailspin Toysの一連の開発ワークフローを進めました。次のことを行いました。

- Codespaceを準備し、Copilot CLIをインストールして、プロジェクトを確認し、用意されていたフィルタリングのIssueを見つけました。
- 星評価を追加し、転送されたブラウザーで結果を確認して、最初のプルリクエスト (PR) を手動でマージしました。
- フィルタリングのIssueから作業を始め、Planモードで方針を決め、Autopilotモードで実装し、Interactiveモードで確認しました。
- カスタム指示でエージェントを導き、既存の `quality-checks` スキルをカスタマイズして、ユニットテスト、Lint、型チェックを実行しました。
- Playwright Model Context Protocol (MCP) サーバーを追加し、実際のブラウザーでフィルタリング機能を試しました。
- 品質保証 (QA) のカスタムエージェントを作成して選択し、要件、テストカバレッジ、スキルの結果、ブラウザーでの検証結果を評価しました。
- フィルタリングの変更全体を確認し、フィルタリングPRでAgent Mergeを許可しました。
- コンテキスト、モデル、共有、オプションのクラウドへの委任に使うスラッシュコマンドを確認しました。

## 作成したもの

このワークショップには、更新した `main` からそれぞれ別のブランチを作成する、2つのPRの節目があります。

1. **星評価:** 既存の `starRating` と、評価がないことを明示する表示をゲームカードに追加します。
2. **フィルタリングと品質確認のワークフロー:** フィルタリングを実装し、指示を更新して機能に適用し、`quality-checks` のレポートをカスタマイズし、QAプロファイルを作成して、関連するテストを追加します。

フィルタリングの計画からPRの作成までは、同じ会話とブランチを使いました。ワークショップを簡潔にするため、これらの作業を1つのPRにまとめました。

## さまざまな検証方法

自動テスト、自分で行うブラウザー確認、MCPを介したCopilotのブラウザー操作など、いくつかの方法でコードを確認しました。`quality-checks` スキルはユニットテスト、Lint、型チェックを実行し、新しい形式で結果を報告しました。QAエージェントは、それらの結果と要件およびテストカバレッジの確認をまとめました。

追加するテストでは、実際に不足している部分を補う必要があります。QAを実行してもテストの追加が不要な場合、それが正しい判断であることもあります。マージを許可する前に、コードと根拠を確認してください。変更があった場合は、影響を受ける検証結果を更新します。

## ベストプラクティス

Copilotに提供するコンテキストとツールが、作業の結果を左右します。このワークショップでは、指示を更新し、スキルをカスタマイズし、QAプロファイルを作成して、MCPサーバーを構成しました。これらのカスタマイズは会話をまたいで再利用し、チームのニーズに合わせて調整できます。指示は標準を定め、スキルは繰り返し実行できるタスクを記述し、カスタムエージェントは専門的な役割を定義し、MCPサーバーは外部ツールに接続します。エージェントの要約だけでなく、実際の変更とツールの結果を確認してください。

タスクに合った**モードとモデル**を選びます。**Plan** は実装前に方針を検討するとき、**Interactive** は対象を絞った変更の進行を把握したいとき、**Autopilot** は範囲が明確なタスクを任せるときに使います。定型的な編集には高速なモデルを、複雑な作業にはより高性能なモデルを選びます。

ツールの種類にかかわらず、コンテキストは重要です。何を、なぜ、どのように作るのかを明確に説明すると、結果が大きく変わります。

## さらに試す

中心となるワークフローは以上です。Copilot CLIには、ほかにも試す価値のある機能があります。

- `/review` を使って、コードレビューエージェントに変更を分析してもらいます。
- `/rubber-duck` を使って、問題について対話し、別の視点を得ます。
- `/fleet` を使って、独立したサブタスクを並行して調整します。
- `/worktree` を使って、別のタスクを隔離します。
- `/delegate` を使って、タスクをCopilotクラウドエージェントに送ります。

## 次のステップ

どのツールも、使い続けることが上達への近道です。実際のコードや趣味のコードに使ってみましょう。何年も作りたいと思いながら手を付けていなかった小さなアプリに挑戦するのもよいでしょう。学んだことをチームで共有し、チームのメンバーからも学びましょう。そして、ドキュメントも引き続き確認してください。

ターミナルからTailspin Toysをさらに拡張したい場合は、オプションの[Foundry Backer Conciergeシリーズ][foundry]に進んでください。別の環境と比較するには、[VS Codeワークショップ][vscode]、[GitHub Copilotアプリのワークショップ][app]、または[Copilotクラウドエージェントのワークショップ][cloud]を確認してください。
