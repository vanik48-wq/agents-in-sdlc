まず、プロジェクトに小さな機能を追加しました。しかし、より大きな変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot CLIは組織の既存の開発フローに沿って動作するため、適切な方法で必要なものを構築できます。このレッスンから、エージェントを活用した一般的な開発プロセスをいくつかのレッスンにわたって進めます。Issueを起点に新機能を作成し、コードが有効で機能が期待どおりに動作することを確かめ、最終的にプロジェクトへ正常にマージします。

> [!NOTE]
> 機能開発を続ける間は、同じ会話とブランチを使います。通常は、作業するファイルの種類ごとに異なるブランチやPRを使いますが、ここでは中心となる概念に集中できるよう、手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub IssueからCopilotの新しい会話を開始します。
- Planモードで要件を定義します。
- Autopilotモードで新機能を実装します。
- コードを確認します。
- 転送されたブラウザーで機能を手動で検証します。

この機能の開発を続けながら、リポジトリの指示ファイルを更新し、既存の `quality-checks` スキルをカスタマイズし、MCPによる検証を追加して、QAエージェントを作成し、機能PRを開きます。

## シナリオ

Tailspin Toysのカタログが増えてきたため、訪問者がカテゴリや販売元でゲームを絞り込めるようにする必要があります。バックログのIssueには機能の概要が記されていますが、カテゴリを組み合わせる方法など、実装前に合意しておきたい詳細があります。Planモードでその方針を決めてから、範囲を明確にした実装をAutopilotに任せます。

## 背景

AIコーディングエージェントを開発フローに取り入れても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 実装内容を記述したIssueから始めます。
2. 構築する内容の計画を立てます。
3. コードを作成して確認します。
4. テストを実行し、コードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューが完了し、継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細はチームや組織によって異なりますが、多くの場合は上記の流れを調整したものになります。

このような標準的な手順に沿うことで、AIが生成したコードが要件を満たし、手書きのコードと同じ確認プロセスを経るようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントはまず計画を作成し、プロジェクトファイルの編集は行いません。
- **Autopilot**: エージェントはコードを書き、テストを実行し、タスクが完了したと判断するまで自律的に反復します。

最初にPlanモードで計画を確認し、その後Autopilotで実装します。

## Issueから開始する

フィルタリングの作業を始める前に、Codespaceに戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespaceに戻ります。停止している場合は、再起動してから続けます。
2. 星評価のPRがマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新してから、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLIを起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を2回押して、**Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべてのIssueを表示します。
8. 矢印キーを使って、**Allow users to filter games by category and publisher** というタイトルのIssueを選択します。
9. <kbd>C</kbd> を押してIssueをプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が表示されます。`#` を使うと、GitHub上のIssueやプルリクエスト (PR) をコンテキストに追加できます。

## フィルタリング機能を計画する

計画を立てることで、Copilotに実装やタスクを任せる前に、機能の実現方法を決められます。複雑な作業では、少し時間をかけて計画を立てるのがおすすめです。Planモードに切り替えて、Copilotに計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押してPlanモードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加したIssue参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilotが計画の作成を始めます。プロジェクトを調査し、最適な方法を検討します。

3. 途中でフィルタリングの動作について質問されることがあります。希望に基づいて回答してください。どの答えも間違いではありません。
4. 計画ができたら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して、計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 自分の決定と合わない部分があれば、Copilotに修正を依頼します。

## Autopilotを承認する

計画の作成と確認が済んだら、実装に進みます。Autopilotを使ってCopilotに作業を任せましょう。

Autopilotでは、Copilotが問題を解決したと判断するまで反復します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みのバージョンに表示される同様の選択肢を選択します。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilotが計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まる場合があります。まず計画を確認してください。Copilotから依存関係の不足やポートの競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決してください。

## 実装を確認して検証する

生成されたコードは、ほかのコードと同じように、マージ前に確認する必要があります。コードを確認し、サイトを実行して問題がないことを確かめましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押してInteractiveモードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルタリングの実装とテストをすべて確認します。
3. 結果をIssueと計画時に決めた内容と照らし合わせます。
4. コードの確認が終わったら、<kbd>Esc</kbd> を押して差分画面を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があればCopilotに解決を依頼します。

## 新機能を試す

コードに問題がないことは確認できました。では、実際に動くでしょうか。前回と同じようにアプリを起動し、Codespacesの転送ポートを通じてサイトを開きましょう。

1. Copilotにアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespacesでポート `4321` が利用可能になったことが通知されたら、**Open in Browser** を選択します。
3. カテゴリによるフィルタリング、販売元によるフィルタリング、および計画で合意した組み合わせを試します。
4. リセット時と検索結果がない場合の動作が、Issueと決定内容に合っていることを確認します。
5. Codespaceに戻り、Copilotに起動した開発サーバーの停止を依頼します。
